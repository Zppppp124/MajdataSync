快速开始

第一次使用只需要完成一次目录识别；之后打开软件就能继续同步。

1解压并运行把发布包解压到普通文件夹，双击 MajdataSync.exe。不要直接在压缩包临时目录里运行。
2识别 Original选择游戏根目录或 MaiCharts\Original，程序会自动定位谱面目录，不绑定盘符。
3读取索引点击刷新索引。已有缓存会快速显示；首次建立完整曲库需要等待一段时间。
建议：批量下载或切换游戏版本前先关闭 MajdataPlay，避免曲目库正在读取文件时产生占用。

曲目库：搜索、难度筛选、勾选与下载

搜索与难度筛选

搜索框支持曲名、曲师、谱师、上传者和标签。右侧难度下拉可以选择 BASIC、ADVANCED、EXPERT、MASTER、RE:MASTER 和其他难度；选定分类后，第二级下拉会按数字顺序列出对应等级，例如 0、1、1+、1?、2、13+、14+。

带小数、+、? 的等级仍保留原值；“宴、藏、狂”等不是标准数字等级的标记会被归入“其他难度”。难度、等级、搜索词、日期和入库状态可以组合筛选。

曲目放在哪个版本

顶部“曲目目标”有三个选项：

置于稳定版只下载并缓存到稳定版游戏目录。
置于测试版只下载并缓存到测试版游戏目录。
共存（两版）先检测稳定版，再检测测试版；两套都存在时下载一次并复制文件和缓存。
只检测到一个版本共存模式只写入存在的那一套目录，不做第二份复制。

三种下载方式

同步新谱面只选尚未下载，或站点哈希已经变化的新版本。
下载所选给曲目卡左上角打勾，再按顶部“下载所选”，只处理勾选曲目。
下载全部/筛选结果适合按日期或搜索条件补抓整个时间段的谱面。
导入 ZIP把本地 ZIP 以文件名建立曲目目录，并展开零散文件。
逐首入库：每首下载成功后立即写入同步索引。即使后续任务中断，已完成的曲目仍然保留，不需要整批重下。

日期更新

点击“按日期更新”，选择上传日期区间并决定是否只同步新版本。适合补抓某次活动、某个发布时间段的曲目。

游戏管理：稳定版与测试版

通道来源更新方式
稳定版MajdataHub 同款 CNB
TeamMajdata/MajdataPlay_Build		逐文件并发下载；每个文件独立校验、保留已完成文件、失败后继续补齐
测试版TeamMajdata/MajdataPlay 的 nightlyFast 加速下载完整 nightly ZIP；解压后安全替换程序文件并清理

稳定版和测试版可以分别设置并记住目录。首次下载当前版本时选择的目录会成为该版本默认目录；之后切换版本时，程序会先检查目标版本目录里是否已有游戏。

已有游戏直接切换到该版本，不重新下载；之后按该版本来源检查更新。
目录存在但没有游戏提示下载该版本完整包，完成后自动切换。
还没有目录先选择该版本目录，再进行首次下载。
两个目录入口页面底部可分别打开稳定版目录和测试版目录。

切换和更新只作用于当前版本自己的目录，MaiCharts、Skins、Cache、RecordOutputs、Logs 与 settings.json 不会被覆盖。

不要在压缩包临时目录运行：从 WinRAR 等临时目录直接双击时，解压软件可能在下载期间清理目录，窗口会突然消失。请先完整解压，再运行 MajdataSync.exe。

为什么稳定版改成逐文件

MajdataPlay_Build 的 CNB 大 ZIP 使用分块流传输，不支持标准 Range 断点续传。下载到约 300 MB 时如果中间网络层断开，服务端再次请求会从第 0 字节发送整包，看起来就是“重新开始”。

1.12.0 改为与 MajdataHub 使用同一个 CNB 仓库，但按仓库清单逐文件下载。已完成文件直接跳过；某个文件中断只补该文件，不再让整个 323 MB 包归零。文件列表来自 CNB 的 smallest_hashes.json，每个文件都按 SHA-256 校验。

实测：完整稳定版共有 1,265 个文件。1.12.0 使用 5 个文件并发，已完整跑通下载、校验和安装，避免单个大 ZIP 在 300 MB 断流后整体重下。

启动与编辑

启动区可以选择 D3D11、D3D12、OpenGL、Vulkan，或进入测试/谱面编辑模式。没有特殊需要时保持默认即可。

网络、线路与下载策略

稳定版

稳定版固定使用 MajdataHub 同款 CNB 仓库，不受“Fast / Proxy / Mirror”下拉影响。CNB 清单和单文件都直接从 CNB 获取，不使用 GitHub 镜像。界面会显示文件进度而不是单个大 ZIP 进度。

测试版

测试版默认使用 Fast，首选 ghfast.top。下载前不会在短时间反复切换线路；发生一次波动时优先重连当前线路。连续失败后才尝试 gh-proxy.com、GitProxy、GHFile 等候选。完整 nightly ZIP 下载、校验、解压后才替换游戏文件。

场景默认线路失败处理
稳定版CNB 逐文件单文件保留并继续补齐，不切换 GitHub 镜像
测试版Fast / ghfast.top优先重连当前线路；连续失败后切换候选
谱面资源本站与同源镜像失败的谱面继续处理其他曲目，再次同步只补缺失项
谱面逐首入库：每首曲目成功后立即保存同步索引。批量任务中断不会让已经完成的曲目重下。
线路仍取决于本机网络：程序只替换普通 HTTPS 下载地址，不安装或接管系统代理。公司网络、防火墙、DNS 和站点限流仍可能影响速度。

在线缓存与皮肤

本地曲目库与在线缓存

顶部“存放位置”可以选：

  • 本地 + 在线缓存：同时写入 Original 和游戏缓存。
  • 仅本地曲目库：只保留可直接游玩的本地谱面目录。
  • 仅在线缓存：只写入 Cache\Net\MajdataNET，适合减少本地曲目文件夹。

“预热在线缓存”会把已经存在的本地曲目转换成游戏在线模式需要的缓存结构和 .sha256 校验文件。

皮肤

皮肤页读取社区皮肤列表，支持下载、重装和直接应用。应用皮肤只会更新 settings.json 里的 Display.Skin，不会覆盖其他设置。

设置与高级设置

常用偏好

可以调整并行任务数、是否下载 PV、是否自动检查新谱面、是否启用谱面镜像以及默认存放位置。各项会自动保存。

读取 settings.json

进入游戏管理页后读取当前配置。内置编辑器显示常用字段；高级设置会列出未在内置表单出现的字段，并提供中文说明、默认值和有效值，支持搜索。页面底部可以“读取当前配置”或“保存高级设置”。

修改前建议：先关闭游戏。保存高级设置后，重新读取一次配置，确认字段已经写入。

下载队列

开始同步后，队列会显示当前阶段、已完成任务数、速度、结果和每首曲目的实时进度。可在任务进行中停止；已完成的曲目和缓存不会因为停止而丢失。

建议：任务进行时不要移动或重命名游戏目录。需要切换游戏版本、安装更新或修改 settings.json 时，先等待当前任务结束或主动停止。

常见问题

窗口下载到一半消失了

先确认不是从 WinRAR 临时目录直接运行。新的发布版会把版本和运行路径写入日志。若仍出现，打开日志文件夹，查看同一时间点是否有 Unhandled UI exception 或运行路径在 Temp\Rar$ 下。

为什么下载速度会变慢？

镜像站、CDN、本机网络和防火墙都会影响速度。程序会自动等待、换线并继续续传，不会因为短时间降速而结束任务；最终必须取得完整包才会完成安装。

切换测试版会不会丢曲目？

不会。切换版本只替换游戏程序文件，保留曲目、皮肤、缓存、成绩输出、日志和设置。仍建议切换前关闭游戏。

索引第一次很慢

首次需要建立完整站点索引。后续启动先显示本地缓存，再在后台校验更新，不需要每次等待完整索引。

ZIP 导入失败

确认压缩包包含 maidata.txt。程序会以 ZIP 文件名建立目录，并防止带有 ../ 的危险路径。
